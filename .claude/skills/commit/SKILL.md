name: commit
description: 변경 내용을 분석해 컨벤션에 맞는 커밋 메시지를 작성하고 확인받은 뒤 커밋한다.
disable-model-invocation: true
---

1. 현재 브랜치가 `main` 이면 멈추고 `/start` 로 브랜치를 먼저 만들라고 안내한다.
2. 브랜치 이름 `<type>/<번호>-...` 에서 이슈 번호를 추출한다.
3. `git status` 와 `git diff --staged` 를 확인한다.
   - staged 변경이 없으면 `git diff` 로 전체 변경을 보고, **논리적 단위로 나눈 커밋 계획**을 제안한다.
     (예: "1) docker-compose Kafka 설정 2) 토픽 생성 스크립트" 처럼)
4. 다음은 절대 커밋하지 않는다. 발견하면 경고하고 제외한다.
   - `.env`, 비밀번호·토큰이 들어간 파일
   - 빌드 산출물(`build/`, `target/`, `*.class`), 대용량 데이터 파일, 로그
5. 커밋 메시지를 작성한다. 형식은 CLAUDE.md의 컨벤션을 따른다.

```
<type>(<scope>): <한국어 요약> (#<이슈번호>)

- 무엇을 바꿨는지
- 왜 그렇게 했는지 (설계 결정이 있다면)
```

6. 커밋할 파일 목록과 메시지를 보여주고 **사용자 확인을 받는다.** 수정 요청이 있으면 반영한다.
7. 확인 후 `git add <파일들>` → `git commit` 실행. `git add -A` 나 `git add .` 는 쓰지 않는다.
8. 여러 커밋으로 나누기로 했다면 다음 커밋으로 넘어가 5~7을 반복한다.
